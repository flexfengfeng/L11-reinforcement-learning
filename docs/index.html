Abstract concepts

A shared loop: act, observe, update.

This demo is a multi-armed bandit: a one-step, stateless reinforcement-learning setting. The agent chooses one action, observes that action's reward, and starts the next independent round. More general reinforcement-learning tasks can include a changing state and delayed rewards.

An agent looks at its situation, takes an action, gets a reward, and updates how it will act next time.

Explore vs exploit — the idea worth keeping

Exploit = use what you know to earn reward now. Explore = try actions to gain information, potentially sacrificing immediate reward. Too little exploration and you can lock onto a mediocre choice; too much and you keep gambling on weak options. ε is literally the knob for this balance.

How is this different from supervised learning?

Supervised (most of L01–L10)Reinforcement (today)
GivenExamples with correct target labelsNo correct-action label; observe a reward for the action selected
Feedback“The right label was X”“That choice earned 1” (never the best)
Sarah exampleClassify a review +/–Learn which banner earns clicks

A missing answer key by itself does not define reinforcement learning; unsupervised methods also work without labels. What makes this an RL example is the repeated action → reward loop and the policy objective.

Key takeaway Reinforcement learning = learning a policy (a habit of acting) from rewards (feedback on actions), while balancing exploration against exploitation. Sequential RL also needs state transitions and long-term returns.
Stretch optional

Different visitors, different best banners.

So far the agent showed one banner to everyone. Real recommenders use context — something known about the situation before choosing. Here the agent sees whether a visitor is new or returning, and keeps a contextual action-value table: a score for each banner per visitor type. This is a contextual bandit, not Q-learning: it estimates immediate rewards and does not bootstrap from future states. Run it and check whether the estimates identify the two different true winners.

Where this leads Add the idea that your action changes the next situation, and you reach full reinforcement learning — optimising long-term reward over a sequence of decisions (chess, robotics, checkout flows). The same loop, scaled up, is also how modern chatbots are tuned: RLHF asks people which of two answers they prefer, trains a reward model on those choices, and uses it as the reward. This introduces the action → reward → update pattern; sequential RL also needs methods for long-term returns.
